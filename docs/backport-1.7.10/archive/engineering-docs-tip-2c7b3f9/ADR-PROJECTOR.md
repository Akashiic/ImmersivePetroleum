# Projector — persistent plans with bounded verification

Qualification update 2026-09-14: implementation and laboratory gates PASS; see `PROJECTOR-QUALIFICATION-2026-09-14.md`. Independent external review, Crucible/pack/multiplayer and release approval remain pending. The technical decisions below remain the design contract.

## Source and player workflow

Primary sources: frozen IP1.21.1 revision `e6cb01df32d4adfd096d49c02bb91e60fef56a15`, `ProjectorItem`, `Settings`, `MultiblockProjection`, `ProjectorScreen`, `MessageProjectorSync` and generated projector recipe; local IP1.12.2 `ItemProjector` was also read for the legacy manual-array/rotation/event conventions. The actual target IE IMultiblock contract was inspected with javap against `libs/ImmersiveEngineering-garden-cloche-test-2.jar`, and Minecraft/Forge GUI, inventory, packet, snapshot and placement-event APIs against `build/rfg/recompiled_minecraft-1.7.10.jar`.

The survival recipe preserves the modern shape `S  / IL /  IW`: glass, two iron ingots, treated wood and a lantern. The available legacy IE electric lantern replaces the modern lantern; the modern item is not present in the pinned legacy registry. Selecting a structure opens an original searchable panel with a native material-model preview, rotation/mirror controls, selectable layer and scrollable material requirements compared with the player's inventory. The item itself has an original code-native wooden housing, steel feet, brass lens and illuminated aperture. Installed Minecraft/IE material models and icons are referenced, not extracted or redistributed.

Use the projector to open selection; confirm enters projection mode. While selected, the unpinned projection follows a targeted loaded block. Use on a block fixes the anchor server-side. Sneak-use unpins; sneak-use again switches selection/projection mode. P opens configuration, F mirrors, and sneak+wheel rotates; these are ordinary remappable Minecraft bindings. Fixed projections remain visible for projectors in the nine legacy hotbar slots, allowing the held building material to be highlighted in white. There is no offhand in native1.7.10. A shader-case skin from modern IE is not emulated; the supplied body/UI are original and the hologram uses fixed-pipeline coloring.

Position transformation applies the modern FRONT_BACK mirror on template X before four quarter-turn rotations, normalizes the rotated bounding rectangle, then centers it at the anchor. Top/bottom slab state is separate from the inventory material. Even rectangular near-edge alignment uses the rotated dimensions, repairing the modern original-dimension parity quirk. Pumpjack's runtime facing convention differs from the other five machines, but all eight planar template transforms remain representable by its formation rotations/mirroring; the projector reports quarter turns of the template, not a claim that every machine defines NORTH identically.

## Exact material rules versus generic IE templates

All six Petroleum IMultiblocks have explicit snapshots of their canonical entries. Each world comparison calls the same `Materials.matches` used by formation, including covered-pipe refusal, actual world slab metadata and required tile state. These templates are exact within the existing formation-material contract. The dedicated probe places/checks the materials of every family and adds negative covered-pipe/top-slab cases.

Other registered IE/third-party IMultiblocks are included using their real `getStructureManual` contract. This target API supplies ItemStack arrays but no `getBlockstateFromStack` or per-cell world-equivalence predicate (the1.12.2 API had a richer conversion). Equal inventory damage therefore cannot certify conveyor direction, piston orientation, ore aliases or arbitrary tile configuration. A matching generic material is shown as an amber candidate, never green or "complete". Its native material silhouette and bill of materials remain usable construction guidance. Dynamic integrations can call `ProjectorCatalog.invalidate()` after changing a manual template; changes to the native registry identity list automatically invalidate snapshots. No correctness claim is made for unsignaled mutation of a third-party template's internals.

Blue ghost models indicate missing material, red outlines conflicts, green outlines exact verified cells, and purple pending/unloaded cells. Fixed projections default to the first incomplete layer, advancing only when the earlier layer is correct; explicit layers can also be selected. This fixes modern's case where a conflicting non-air block did not increment the incomplete-layer counter. Generic candidates cannot silently advance to a certified complete structure. The complete green volume is emitted only after all entries have actually been verified correct.

## Server ownership and creative construction

Settings have a schema, a nonzero server-issued128-bit item token, revision, native multiblock identity, rotation/mirror, dimension, anchor and layer. Primitive types/ranges are strict. Malformed settings stay in the item and are not silently replaced by defaults. A fixed155-byte server-only action protocol carries no world coordinates or arbitrary NBT. Server tick processing verifies the currently held item, selected slot, token, revision, inventory container and native template identity. Replayed/stale revisions and swapped slots are rejected. Netty only places the latest authenticated sender action in a mailbox; world/inventory work happens on server ticks. The mailbox holds at most one pending action per connected sender, logout purges it and a server-instance change clears old state. Up to32 sender actions are processed per tick, with coalescing and eventual processing rather than a new functional player cap.

Pinning uses the ordinary server item-use position, live loaded block, world identity, edit permission and player distance. Client render distance is independently configurable and never becomes authority to mutate distant world coordinates. Ordinary survival projection never creates blocks or consumes inventory building material.

Sneak-use on an unpinned projector in creative mode can start explicit construction for an exact Petroleum template. Its separate round-robin job retains a cursor, uses the configured work budget and waits at unloaded chunks. It never overwrites occupied cells or inventories, checks player edit permission, posts the real Forge player PlaceEvent and restores a canceled publication using its BlockSnapshot. A callback failure stops the job rather than silently continuing. Reentrant tick calls cannot advance it. Losing creative mode, switching the held owner/revision, changing world, moving beyond the 64-block construction radius, logout or disabling the feature cancels work. It resumes after a needed chunk loads naturally. This is a conservative adaptation of modern's synchronous creative placement, which can replace occupied cells; the backport exposes partial results/conflicts instead of erasing player content. Jobs are not persisted: after restart a player can start again, and already correct cells are skipped. There is no automatic multiblock formation; the player's hammer remains the final native assembly operation.

## Cost, render state and invalidation

The default128 verification budget is shared across all visible fixed hotbar projectors, with a retained cursor and rotating slot priority. Unchecked cells are PENDING. World status refreshes over subsequent client ticks; it is a recent checked snapshot, not a synchronous promise that a block cannot change between verification and rendering. Rendering does no full world scan. Queries test block/chunk presence before invoking formation rules and never request chunk tickets, world generation or worker-thread world access. The native predicates still have their ordinary per-cell cost, including small coordinate objects.

Template and transformed coordinate arrays are cached. Native inventory material geometry is compiled into display lists by block/world metadata and reused; model generation is not repeated for every cell/frame. Per-frame work still scales with displayed cells and projections: there is no measured FPS/TPS claim. The static original item mesh is constructed once. Hotbar/held identity, NBT revision, pose, selected template, world and dimension changes invalidate the corresponding views. World changes/disconnect and resource reload release display lists; resource reload invalidates template snapshots too.

World rendering restores matrix, enable/current/color-buffer/depth-buffer/texture/line/lighting state. GUI preview owns/restores scissor, lighting and depth/matrix changes. Its depth clear is confined to the preview rectangle. Native OpenGL1.4 constant blending provides a colored translucent silhouette; older contexts use ordinary alpha blending. Native renderer behavior, Angelica compatibility, unsupported third-party inventory renderers, shader packs and perceived visual quality require actual client checks; the isolated GL probe does not establish all of those combinations.

## Written gates and output hooks

`ProjectorDomainTest` contains ten tests: transformed bounds/uniqueness, actual Derrick formation geometry in eight poses, rectangular golden coordinates, settings roundtrip, malformed NBT, fixed packet roundtrip/corruption, pending-before-verified behavior, changed/unloaded cursor refresh and candidate-versus-exact distinction.

`tools/run-projector-campaign.ps1` creates a fresh world and runs three boots with exclusive runtime mutex, loopback binding, deadlines, process-tree cleanup, exact configuration restoration, required markers and saved-region hash:

1. `PROJECTOR_SURVIVAL_PASS`: real recipe lookup, server token/settings, revision replay rejection, slot and distant-pin refusal, and no creative build from survival.
2. `PROJECTOR_MATERIAL_PASS`: actual settings reload, all six native formation-material families, covered-pipe refusal and world top-slab distinction.
3. `PROJECTOR_CREATIVE_PASS`: budget3, one canceled Forge PlaceEvent restored, reentrant tick refused, distance cancellation, no force-loaded chunk and eventual resumption.

Every boot requires `PROJECTOR_PROBE_PASS mode=... master=100079,80,100000`; only successful campaign cleanup publishes `PROJECTOR_CAMPAIGN_PASS`. The runner parsed with zero PowerShell parser errors; it has not been executed in this subtask.

Real-client opt-in `-Dimmersivepetroleum.projectorRendererProbe=smoke` starts an isolated integrated world, draws a client-only projection fixture with missing/correct/wrong blocks, validates48 family/rotation/mirror preview combinations and relevant GL-state restoration, then captures `screenshots/projector-world-probe.png` and `screenshots/projector-gui-probe.png`. Its marker is `PROJECTOR_RENDERER_PROBE_PASS`. The fixture explicitly refreshes a client inventory item and is not a substitute for the dedicated server authority tests or real survival use.

Shared registration/config/language hooks are listed in `PROJECTOR-LANG-HOOKS.txt`. No shared registry, proxy, language file, build/version file or existing machine source was edited by this family implementation.
